# Back office design system

One stylesheet (`app.css`), one engine for list screens (`list-engine.js`), one place for navigation (`ux-review/tools/sync.py`).
Do not copy styles into pages. If a pattern is missing, add it to `app.css` and use it everywhere it applies.

## Page anatomy

```
<main class="pg" id="main">
  <div class="hd"><div class="hdt"><h1>Page name</h1><span class="sub">One short sentence.</span></div><div class="hda">actions</div></div>
  section navigation (generated by sync.py)
  feedback (status, errors)
  content
</main>
```
* **Title** is the name of this page (never the section name). 24px, one per page.
* **Subtitle** is one sentence. Rules and caveats go in a footnote (`<p class="note">`) at the end.
* **Section navigation**: `nav.tabs` (groups) and `nav.subtabs` (pages in the group). Never use header buttons to reach a sibling page. Edit `sync.py` to change navigation; do not hand-edit the sidebar or tabs.
* **Detail pages** (a record, a multi-part job) use a breadcrumb above the title (`<a class="crumb">‹ Back to X</a>`), have no section tabs, and return to the list in the same state.

## Actions

| Kind | Class | Rule |
|---|---|---|
| Primary | `btnp` | One per screen, in the header (or the status banner). Never repeated in rows. |
| Secondary | `btn` | Header: 40px. In rows and tables: `btn sm` (32px), one per row. |
| Navigation | `lnkb` | Quiet link-style button for "go elsewhere" and for secondary row actions (`Open stock ›`, `Dismiss`). |
| Destructive | `btn danger` / `btnd` | Quiet in rows. Loud (`btnd`) only inside the confirmation of an irreversible action. |
| Menu | `details.xm` | Export and similar. Closes on choice, outside click and Escape (shell.js). |

Row actions: put them in `<span class="acts">`. The first bordered button is the row's main action; others are quiet. If the whole row is the action, make it a row link (below) and show no button.

## Tables and lists

* `.card.tbl > div (min-width) > .th + .tr…` with `grid-template-columns` shared by header and rows. Tables scroll sideways on a phone by default.
* **Row link**: `.tr.rl` with one `.rlb` (button or link, `::after` covers the row) and a `.go` chevron. Give it an `aria-label` that names the record.
* **Phone stacking** for work lists whose key columns would scroll out of view: add `m-jr`, `m-wait`, `m-pay`, `m-rec`, `m-coa` or `m-tb` (see the end of `app.css`) or write a new `m-*` variant. Reference tables (ledger, statements) keep scrolling.
* **Status**: show a `.pill` only for exceptions. Do not label every row "Posted/Active".
* **Empty**: `.empty` (title, one line, optional "Show everything"). Two kinds: "nothing yet" and "nothing matches".
* **Filters**: `.band` with `.fc` chips (`aria-pressed`), group labels `.gl`, separator `.vsep`. Default to the useful view ("Needs attention"). Secondary filters behind "More filters" (`.more`).
* **Summary**: one `.banner` (warn/good) or `.statrow` (one strip, 3–4 figures). Never a row of separate tiles that repeat the table.

## Feedback

* Success: `.ok` with `role="status"`; add `.toast` and a Dismiss `lnkb` for banners that come from an action.
* Error for the whole form: `.alert` with `role="alert"` and a count ("3 things need fixing…").
* Error for a field: `.ferr` under the field, field has `aria-invalid="true"`. Show **all** errors at once and focus the first.
* Say what happened and what changes ("Ikoyi outlet is added."), not just "Saved".
* Confirm only irreversible or far-reaching actions. Reversible toggles (Switch off ↔ Switch on) act at once and say so.

## Forms

* `.fld > label.lbl > input.field`. Mark optional fields "(optional)", not required ones.
* Choose the control from the data: up to 6 options → chips (`.seg .chip`, single or multi, `exclusive` for "All"); more → text with suggestions; dates → `type="date"` shown to people as "1 Nov 2026"; numbers → `inputmode="decimal"`; a sentence → textarea.
* Type values people must remember are not typed: no "Outlet, Production site or In-flight site" placeholders.
* Primary button on the left of the footer, Cancel after it. Primary names the action ("Add location"), never "Submit".

## Overlays

| Use | When | Size |
|---|---|---|
| **Full page** | Several parts, line items, or a step-by-step job. Has a breadcrumb. | – |
| **Drawer** `aside.drawer` | A record with context, or 3–5 fields, and the list stays in place. | 440px, full height |
| **Dialog** `aside.drawer.dlg` | A bounded question: 1–2 fields, a reason, a confirmation. | 480px, centred, height of its content |

Never split the screen to show a table beside a drawer. The scrim covers the page. Behaviour (shell.js, do not re-implement): Escape closes, focus stays inside, the page behind is inert, focus returns to the button that opened it. Clicking the scrim closes. A drawer or dialog has a title, a Close button, the form, then the footer actions.

## Type, spacing, size

Tokens in `app.css` `:root`: `--fs-1…6` (12, 13, 14, 16, 18, 24px), `--sp-1…5` (4, 8, 12, 16, 24px), `--ctl-sm/ctl/ctl-lg` (32, 40, 44px). Body text is 14px, supporting text 13px, never below 12px. Interactive controls are at least 32px (40px in headers and forms, 44px on touch screens).

## Responsive

390px, 768px, 1280px and 1920px are all checked. The sidebar becomes a top strip under 768px. Drawers fill the width under 640px; dialogs keep a 16px margin.
